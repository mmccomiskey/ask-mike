ask-mike

Building a language model from scratch, then building the version that actually works, and understanding exactly why they differ.

Track A — from scratch not built

A decoder-only transformer written by hand in PyTorch. Tokenizer, embeddings, multi-head self-attention, residuals, training loop, sampling. No model classes off the shelf. Trained on a corpus of prose about me, then exported and run here in the browser via a forward pass reimplemented in plain JavaScript.

It will overfit and it will say untrue things. That is the intended result, and measuring it precisely is the point.

Track B — the one that works not built

Retrieval over a curated knowledge base, embedded at build time into a static file. Similarity search runs client-side, because at a few hundred chunks that genuinely is the right answer and no vector database is warranted. Answers cite their sources and decline what the corpus cannot support.

Status

Foundations. This page exists to prove the deploy pipeline works before there is anything interesting to break — so that later, when model output looks wrong, it is never because of a stale build.
